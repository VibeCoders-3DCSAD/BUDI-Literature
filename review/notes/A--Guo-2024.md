# Optimal test case generation for boundary value analysis

`A--Guo-2024` — Guo, X., Okamura, H., & Dohi, T. (2024), *Software Quality Journal* 32, 543–566. DOI 10.1007/s11219-023-09659-9

## Summary

The authors define boundary coverage distance (BCD), a metric for how thoroughly a set of test inputs covers the boundaries of an input domain, and derive three Markov chain Monte Carlo (MCMC)-style algorithms that optimise test-input sets to minimise BCD under a random testing scheme. Experimental validation on five subject programs with mutation faults shows most BCD-based methods detect faults (kill mutations) better than random testing (RT) and adaptive random testing (ART), and A1 optimized with the mean-operation variant (`A1_BCDmean`) killed the most mutations overall.

## Problem and Motivation

Boundary value analysis (BVA) is a widely used black-box technique that tests input values at the boundaries where software behaviour is expected to change. The open problem is how to *generate* boundary-focused test inputs well and how to measure how much of the boundary a test set actually covers.

## Method

**Design.** Methodological paper: definition of the BCD coverage metric, proposal of three test-input generation algorithms, and a comparative fault-detection experiment.
**Sample.** Five real-world programs (Table 2/Table 3) with mutation faults injected (Table 4); the set of input-domain boundary points for each program. Not a human sample.
**Context.** setting: software-testing literature (symbolic execution, random testing, adaptive random testing, concolic testing) and C programs instrumented with Gcov coverage.

- BCD measures how far a test set sits from the boundary: computed as the maximum, over boundary points/components, of the minimum distance to the nearest test input (max operation), with a mean-operation alternative that gives every boundary point equal weight.
- Algorithm 1 generates an initial random test set and iteratively proposes replacements that reduce the BCD value (max or mean variants, or the mean of both, `BCD_mean`).
- Algorithm 2 optimises per boundary point/component; Algorithm 3 follows a similar structure to the MCMC method.
- Fault-detection experiments compare 7 method combinations (3 algorithms × BCD computations) with RT, ART, and concolic testing (KLEE) using mutation kill rates.

## Software

C programs (miniSAT, and others per Table 2) with Gcov for coverage instrumentation; KLEE for symbolically generated test inputs; mutation testing for fault injection. Artifacts are described in the paper; no separate repository is cited in the conversion.

## Key Findings

- num: The BCD metric and the three algorithms (A1, A2, A3) generate boundary-focused test inputs; the approach "has the potential to generate boundary values and improve the effectiveness of software testing" (page 1).
- num: Most BCD-based methods showed better fault-detection ability than RT and ART, and better kill rates than concolic testing, because concolic testing is not good at detecting OBOB (off-by-one-boundary) bugs (page 18).
- num: Test inputs generated by `A1_BCDmean` killed more mutations than the other methods (page 18).
- num: For the same number of iterations, A1 with `BCDmean` accepts more candidate replacements than A1 with `BCDmax`, so reducing BCD computed with the mean operation is more helpful for test-set optimization than the max operation (Table 6, page 18).
- num: A2 and A3 had slightly higher acceptance rates than `A1_BCDmean`, but with large numbers of boundary points, judging each boundary point's coverage distance does not give as good a result (page 18).
- num: KLEE generated only one test case for the miniSAT program, illustrating the difficulty of testing that program with symbolic methods (page 18).

## Limitations and Gaps

- The evaluation is on five C programs with injected mutation faults; boundary-testing results are reported as kill rates and acceptance rates, not as a statistical comparison with confidence intervals.
- The paper targets low-dimensional numeric input domains (boundary points and line segments); BUDGIE's rule-based classifier inputs include categorical and ratio features, so boundary generation generalises only where inputs are ordered/numeric.
- `BCD_mean` variants are recommended on optimization-acceptance grounds (Table 6) and mutation-kill results (Table 5), but the paper does not report a formal statistical test comparing the seven methods.

## Definitions

- **Boundary value analysis (BVA)** — A black-box testing technique using input values at the boundaries where significant changes in behaviour are expected.
- **Boundary coverage distance (BCD)** — A metric of the distance of a test set from the input-domain boundary; smaller BCD means closer to covering the boundary.
- **Mutation testing / kill rate** — Injecting faults into a program and measuring the share of injected faults a test set detects.
- **OBOB (off-by-one-boundary) bugs** — Defects whose failure is located at input boundaries.

## Key Equations

- Lower limit: BCD is the maximum over boundary components of the minimum distance from the test set to that boundary.
- Upper limit: computed over boundary components with the max operation (Section 3.2).
- `BCD_mean = mean(BCD_max + BCD_mean)` — combined mode used by Algorithm 1.

## Remember This

- BCD (boundary coverage distance) quantifies boundary coverage of a test set; three MCMC-style algorithms generate boundary-focused inputs.
- BCD-based methods beat RT, ART, and concolic testing on mutation kill rates; `A1_BCDmean` killed the most mutations.
