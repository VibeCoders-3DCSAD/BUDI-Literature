# Review Synthesis

The only **hand-written** part of `review/`. Everything else in this tree is
generated by `scripts/build_matrix.py` and will be overwritten.

Use this directory for the cross-paper reading that no single summary can hold:
comparison, argument, and narrative.

## What belongs here

| Kind | File naming |
| :--- | :--- |
| One file per outline section | `{section-id}.md` (e.g. `algorithms.md`) |
| Cross-cutting argument or method note | `{topic}.md` |
| A pointer to a paper or module | `_index.md` |

Section ids match `config/taxonomy.yaml`: `pfm`, `pfm_apps`, `algorithms`,
`methodology`, `evaluation`.

## Ground rules

1. **Cite the paper id.** Every claim traces to a `paper_id` in
   `review/literature-review-matrix.md`, and to a locator in the note's evidence
   table. Never cite a paper you have not extracted.
2. **Numbers come from `review/data/effects.csv`.** Do not retype a statistic
   from memory; look it up, and keep the locator.
3. **Distinguish what a paper claims from what you conclude.** Mark your own
   inference as such.
4. **Note disagreement rather than resolving it.** Two papers contradicting each
   other is a finding about the field, and belongs in the prose.
5. **Say when the corpus is thin.** A section with 2 extracted papers cannot
   support a confident claim; write it up as provisional and name the gap.

## Current state

Extraction is in progress (2 of 93 papers carry a summary as of 2026-09-30), so
most modules have no assigned papers and `review/data/themes.csv` shows zeros
throughout. Treat any synthesis written now as provisional; the honest coverage
figure is in that file, not in this prose.

Start with `review/data/screening.csv` for what is extracted, and
`review/data/themes.csv` for what is missing.
